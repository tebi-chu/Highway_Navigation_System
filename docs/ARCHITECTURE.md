# MVPアーキテクチャ

## データフロー

1. `CoreLocationService`が位置、速度、course、水平精度を取得する。
2. `MapMatcher`がGPS点を周辺の有向道路リンクへ射影し、距離、方位差、直前リンクとの接続性を評価する。
3. `UpcomingPointEngine`が判定リンクから予定経路を前方へたどり、道路上距離が正の地点を近い順に最大6件返す。
4. 同エンジンが実測速度とリンク標準速度から通過予定時刻を計算する。
5. `NavigationViewModel`がSwiftUIに表示状態を提供する。

目的地は開始時に選択するが、目的地点は案内表示の打ち切り条件にはしない。目的地を通過した後も、現在の道路リンクから前方へグラフ探索を続け、次の地点を最大6件表示する。

## 現在のJCT方針

道路リンクは複数の`nextLinkIDs`を保持できる。MVPでは先頭を選択するが、後続版では目的地から得た`PlannedRoute`をエンジンへ渡し、JCTごとの選択リンクを明示する。

## 実データへの移行条件

- 上下線を別の有向リンクとして収録する。
- 各地点は緯度経度だけでなく、所属リンクとリンク始点からの距離を持つ。
- ICは本線通過点、入口、出口を混同しない。
- SA・PAは方向ごとに別地点として扱う。
- 路線変更時もリンク接続が途切れないよう、JCTランプを収録する。
- 出典、ライセンス、データ版、取得日をリリース単位で記録する。
- 店舗ブランドは設備カテゴリと別に保持し、名称バッジで識別する。企業ロゴ画像は各権利者から正式な利用許諾を得たアセットだけを表示する。

## 最初の実道路MVP

- C4 首都圏中央連絡自動車道：海老名ICから久喜白岡JCT、上り・久喜方面
- E4 東北自動車道：久喜白岡JCTから鹿沼IC、下り・宇都宮方面
- 久喜白岡JCTで道路名、方向、方面を切り替える。
- 道路形状と地点座標はOpenStreetMap（ODbL 1.0）を使用する。
- 地点順序はNEXCO東日本のドラぷらおよび公開路線資料と照合する。
- SA・PA設備は現時点でトイレのみを表示し、店舗を含む詳細設備は公式情報との個別照合後に追加する。
